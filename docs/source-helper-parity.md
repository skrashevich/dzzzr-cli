## Файловый протокол

Сначала GET `admin/admin.php` с Basic-аутентификацией организатора, затем POST
`admin/tinymce/jscripts/tiny_mce/plugins/filemanager/stream/index.php` с полученными
cookies и multipart: `cmd=fm.upload`, `path={0}/games/GAME_ID`, `domain=`,
`name0=имя без расширения`, `upload=Загрузка`, бинарный `file0`.
Текст multipart остаётся UTF-8, как у Python requests; формы уровней — Windows-1251.

Проверяются маркеры `#message.upload_ok` и `#error.file_exists`, а не только HTTP 200.
При существующем файле возвращается `already_exists=true`; содержимое не сравнивается
и файл не перезаписывается. Публичный URL содержит текущий город и целевую игру.
В отличие от `split('.')[0]` в оригинале, удаляется только последнее расширение:
`map.final.png` сохраняет имя `map.final`.

## Пакетная заливка

Весь JSON проверяется до первого изменения движка: структура и типы, обязательные
значения, кодировка, сложности и повторы кодов, числовые ограничения. В режиме
update дополнительно проверяется принадлежность всех ID игре. Записи выполняются
по порядку; первая ошибка останавливает пакет и возвращает уже записанные ID.
Автоматического rollback/retry нет: сетевой сбой не доказывает, что сервер не сохранил
последний уровень. Перед повтором create требуется проверить список уровней.

`update` — полная замена моделируемых полей, а не patch. Нулевые числа, пустой текст,
списки и неуказанные флаги очищают прежние значения. Служебные неизвестные поля
и порядок существующего уровня сохраняются. Обычный `admin-update-level` остаётся
частичным обновлением. HTML в JSON передаётся как есть; переводы строк и форматирование
PDF восстанавливает LLM. Файлы загружаются отдельно, их возвращённые URL вставляются
в подготовленный JSON. Технический уровень автоматически не добавляется.

## PDF → LLM → движок

Pure-Go парсер внутри приложения извлекает страницы, текст с расположением,
ссылки-аннотации и изображения; ни заголовки сценария, ни номера первых служебных
страниц не зашиты в парсер. LLM сопоставляет содержание с полями `LevelParams`,
отделяет руководство/шаблоны от уровней, собирает продолжения с разных страниц,
уточняет неоднозначности и вызывает проверку плана до заливки.

`read_pdf` возвращает до 10 страниц, общее количество и `has_more`. Изображения
возвращаются как метаданные с SHA-256, без base64 в контексте модели.
`admin_upload_pdf_image` повторно читает выбранную страницу и загружает изображение
по `image_id`, не передавая весь PDF в движок и не создавая временные пользовательские
файлы. JPEG без масок сохраняются без перекодирования; остальные поддерживаемые
изображения экспортируются в PNG без потерь.
Для известных вхождений изображений возвращаются координаты и ближайший текст; неизвестное размещение помечается явно и требует уточнения при неоднозначности.

Содержимое PDF считается недоверенными данными: инструкции из документа не меняют
политику агента и не разрешают дополнительные действия. Внешние URL сохраняются,
но не скачиваются парсером. Зашифрованные PDF отвергаются. `requires_ocr` обозначает
отсутствие извлекаемого текста (скан либо пустая страница); OCR здесь не реализован.

Чтение PDF доступно в readonly; загрузка картинки/сценария и технический уровень
подчиняются общей политике readonly/approve/full. Пути ограничены `DZZR_FILES_ROOT`.
MCP и встроенный агент используют один каталог инструментов.

## Проверка

Тесты используют синтетический PDF и локальные HTTP/LLM-заглушки. Приложенный
пользователем 72-страничный PDF проверен локально полностью: 72 страницы,
5 встроенных изображений, 14 ссылок; коды, спойлер и буквальные HTML-URL сохранены.
Сам документ и его игровой контент в репозиторий не включены.
Боевые игры не изменялись; качество смыслового разбора зависит от выбранной LLM.
